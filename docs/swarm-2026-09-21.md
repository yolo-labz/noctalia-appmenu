## Hypothesis and actual finding

**Hypothesis:** the legacy AppMenu popup implementation prevents a populated
Help menu from becoming visible. **Falsified:** the original plugin in a fresh
private session visibly renders its Help dropdown. Baseline mouse coordinates
(397,15) then (455,247) opened About Okular, with its app PID confirmed in niri.
The earlier R5b invisible-dropdown failure is **not reproduced** and its exact
historical cause remains unknown. No runtime fix was justified or made.

Actual harness fault: the long Pi scratch root exceeds Unix `SUN_LEN`, preventing
niri from creating its IPC socket (`baseline-runtime.txt`). Fresh short owned
`/tmp/r5c-*` roots restore IPC without any global environment fallback. This is
not claimed as the cause of R5b's earlier failure (which used short roots).

Traced shared callers: BarWidget ordinary click and lazy-expansion completion
call AppmenuPopupWindow.openAt; shared MenuRow emits itemActivated through the
popup to BarWidget.fireClick. Nested SubmenuPopup is unchanged. Architecture,
fallbacks and QML style tokens are unchanged.
